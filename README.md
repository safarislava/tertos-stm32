# Тетрис на STM32: текущее состояние

Состояние на 09.10.2026. Платформа: STM32F407VGT6, STM32 HAL, FreeRTOS, C.

## Что реализовано

- Ввод с матричной клавиатуры через PCA9538: опрос кнопок и передача событий в очередь. Повтор при удержании подавляется; отсутствие кнопки или ошибка чтения возвращают `B_NONE`.
- Рантайм тетриса: фигуры, движение, повороты, автоматическое падение, столкновения, закрепление, очистка строк, счёт, пауза и проигрыш.
- Интерфейс передачи состояния отображению. Драйвер монохромного OLED 128×64 присутствует, но отдельная задача отображения и отрисовка игры пока не реализованы. `oled_Init()` из текущего кода запуска не вызывается.

## Как устроена система

```text
Клавиатура → Task_UserInput → очередь кнопок → Task_Game
                                              ↓
                                     очередь копий TetrisGame
                                              ↓
                                  будущая задача отображения
```

`main.c` инициализирует HAL, GPIO, I2C1 и USART6, создаёт объекты FreeRTOS и запускает планировщик. Сейчас созданы две задачи: `Task_UserInput` и `Task_Game`.

- `userInputQueueHandle`: до 16 событий с кодами `enum Button`.
- `tetrisGameQueueHandle`: одна копия `TetrisGame`. Новое состояние заменяет непрочитанное старое. Начальное состояние отправляется сразу после инициализации игры.

Игрой владеет только `Task_Game`. Он ждёт кнопку до 10 мс, измеряет прошедшее время через `HAL_GetTick()`, обновляет падение и затем применяет полученную кнопку. При изменении состояния отправляет копию в очередь отображения.

## Правила и данные рантайма

- Доска: `board[20][10]`, обращение `board[y][x]`. Начало координат сверху слева; `x` растёт вправо, `y` вниз. `0` — пусто, `1` — закреплённый блок.
- Падающая фигура хранится отдельно в `active`: тип, поворот `0…3`, координаты `x/y`. Семь типов имеют готовые шаблоны 4×4 с шириной и высотой занятой области.
- Фигура выбирается через `rand()` и появляется сверху по центру. Поворот пробуется на текущих `x/y`; если возникает столкновение, он отклоняется.
- Каждые 500 мс — шаг вниз. Когда шаг невозможен, фигура закрепляется, полные строки удаляются, остальные опускаются, появляется новая фигура. За каждую удалённую строку начисляется 100 очков.
- Режимы: `TETRIS_RUNNING`, `TETRIS_PAUSED`, `TETRIS_GAME_OVER`. Если новая фигура не помещается, наступает проигрыш. Новая фигура и продолжение после паузы получают полные 500 мс до падения.

| Кнопка | Действие |
|---|---|
| Влево / вправо | Сдвиг на одну клетку |
| Вверх | Поворот по часовой стрелке |
| Вниз | Один шаг вниз; при препятствии — закрепление |
| Пауза | Пауза / продолжение; после проигрыша — новая игра |

## Где искать код

| Файл | Назначение |
|---|---|
| `Core/Src/main.c` | Инициализация платы и запуск FreeRTOS |
| `Core/Src/freertos.c` | Задачи, очереди, таймер обновления и перевод кнопок в команды |
| `Core/Inc/tetris.h` | Структуры, константы и API игровой логики |
| `Core/Src/tetris.c` | Игровая логика без зависимостей от HAL и FreeRTOS |
| `Core/Src/tetris_shapes.c` | Семь фигур и четыре поворота каждой |
| `Core/Inc/tetris_runtime.h` | Получение копии игры через FreeRTOS |
| `Core/Src/kb.c`, `Core/Src/pca9538.c` | Клавиатура и расширитель портов |
| `Core/Src/oled.c` | Драйвер OLED и графические примитивы |

## Подключение отображения

В будущей задаче отображения подключить `tetris_runtime.h` и получать состояние в локальную структуру. Фрагмент внутри цикла задачи:

```c
TetrisGame frame;
if (tetris_receive_game(&frame, portMAX_DELAY))
{
    // tetris_cell(&frame, x, y) возвращает 0/1 для клетки доски.
    // По frame.phase и frame.score отображаем режим и счёт.
}
```

`tetris_cell()` объединяет закреплённые блоки и падающую фигуру. Размер клеток в пикселях, ориентацию экрана и оформление выбирает слой отображения. `wait_ticks` у `tetris_receive_game()` задаётся в тиках FreeRTOS; для ограниченного ожидания использовать, например, `pdMS_TO_TICKS(100)`. Очередь рассчитана на одного потребителя.

Остаётся создать задачу отображения, инициализировать OLED и реализовать отрисовку. Клавиатура и экран используют один I2C1: при добавлении второго потока нужен общий мьютекс для доступа к шине. Сейчас его нет.

## Проверки и сборка

Из корня репозитория:

```sh
sh tests/run_tests.sh
```

Скрипт собирает игровую логику и запускает 17 тестов: геометрия фигур, движение, таймер, столкновения, очистка строк, пауза, проигрыш и 20 000 шагов со случайными командами. HAL, FreeRTOS и оборудование эти тесты не запускают.
